# GoLedger 安卓端热更新可行性评估

> 评估日期：2026-05-06  
> 项目类型：Flutter 记账应用  
> 目标：无需重新发布 APK 即可更新应用代码和资源

---

## 一、热更新需求分析

### 1.1 业务场景

| 场景 | 频率 | 是否需要热更新 |
|------|------|--------------|
| 修复紧急 Bug（如计算错误） | 低频 | ✅ **强需求** |
| 调整 UI 样式/文案 | 中频 | ✅ 推荐 |
| 新增小功能（如新品类图标） | 中频 | ✅ 推荐 |
| 修改后端 API 地址 | 低频 | ✅ 推荐 |
| 大版本功能迭代 | 低频 | ❌ 建议走应用商店 |
| 修改权限/添加依赖 | 低频 | ❌ 必须走应用商店 |

### 1.2 核心诉求

- **快速修复线上 Bug**：避免等待应用商店审核（1-7天）
- **灰度发布**：小范围测试新功能，降低风险
- **A/B 测试**：不同用户看到不同 UI 方案
- **降低发版成本**：减少用户手动更新的摩擦

## 二、Flutter 热更新技术方案对比

### 方案一：Shorebird（官方推荐）⭐⭐⭐⭐⭐

**简介**：Flutter 团队成员创建的商业化热更新服务，类似 React Native 的 CodePush。

#### 技术原理
- 编译时生成 Dart AOT 快照（snapshot）
- 运行时从服务器下载新快照并替换
- 仅支持 Dart 代码更新，不支持原生代码/依赖变更

#### 优势
- ✅ **官方背书**，与 Flutter 版本同步更新
- ✅ **零代码侵入**，只需 CLI 工具打包
- ✅ **免费额度**：个人开发者 5000 次/月免费
- ✅ **支持灰度发布**、回滚、版本管理
- ✅ **自动检测更新**，用户无感知

#### 劣势
- ❌ **商业服务**，超出免费额度需付费（$20/月起）
- ❌ **依赖第三方**，服务稳定性受限
- ❌ **国内访问慢**，需自建 CDN 加速
- ❌ **不支持原生代码**，无法修改 AndroidManifest.xml

#### 适用场景
✅ **强烈推荐用于 GoLedger**  
- 纯 Dart 代码修改（UI、业务逻辑）
- 快速修复线上 Bug
- 小团队/个人开发者

#### 集成成本
- **时间**：1-2 天
- **难度**：⭐（极低）
- **维护**：⭐（几乎零维护）

---

### 方案二：自建热更新系统 ⭐⭐⭐

**简介**：基于 Flutter 的动态化能力，自行搭建更新服务。

#### 技术路线

**A. 基于 Dart VM 的动态化（不可行）**
- Flutter Release 模式使用 AOT 编译，无法动态执行 Dart 代码
- ❌ **此路不通**

**B. 基于资源包的热更新（可行但受限）**
```
1. 将 UI 配置、文案、图片等打包为 JSON/Asset
2. 启动时从服务器下载最新配置
3. 根据配置动态渲染 UI
```

#### 优势
- ✅ **完全自主可控**，无第三方依赖
- ✅ **免费**，只需服务器存储成本
- ✅ **国内访问快**，可部署到自己服务器

#### 劣势
- ❌ **只能更新配置/资源**，无法更新 Dart 代码逻辑
- ❌ **开发成本高**，需自建更新框架
- ❌ **维护成本高**，需处理版本兼容、回滚等
- ❌ **灵活性差**，UI 必须提前设计为可配置

#### 适用场景
- 仅需更新文案、图片、配置参数
- 有专职团队维护更新系统
- 对第三方服务有强烈抵触

#### 集成成本
- **时间**：2-4 周
- **难度**：⭐⭐⭐⭐（高）
- **维护**：⭐⭐⭐⭐（持续投入）

---

### 方案三：混合方案（WebView + Flutter）⭐⭐

**简介**：部分页面用 H5 实现，通过 WebView 加载，可随时更新。

#### 技术实现
```
核心页面（首页/记账）→ Flutter 原生
次要页面（帮助/活动）→ H5 WebView
```

#### 优势
- ✅ H5 部分可随时更新
- ✅ 技术成熟，风险低

#### 劣势
- ❌ **体验割裂**，H5 性能差
- ❌ **开发成本高**，需维护两套代码
- ❌ **不适合记账应用**，核心功能无法热更新

#### 适用场景
❌ **不推荐用于 GoLedger**  
记账应用核心是流水录入和统计，必须保证流畅体验，不适合 H5。

## 三、推荐方案：Shorebird

### 3.1 为什么选择 Shorebird

| 维度 | 评分 | 说明 |
|------|------|------|
| **技术成熟度** | ⭐⭐⭐⭐⭐ | Flutter 官方团队背书 |
| **集成难度** | ⭐⭐⭐⭐⭐ | 零代码侵入，CLI 工具一键打包 |
| **维护成本** | ⭐⭐⭐⭐⭐ | 几乎零维护 |
| **功能完整性** | ⭐⭐⭐⭐ | 支持灰度、回滚、版本管理 |
| **成本** | ⭐⭐⭐⭐ | 个人开发者免费额度足够 |
| **国内可用性** | ⭐⭐⭐ | 需自建 CDN 加速（可选） |

### 3.2 集成步骤（预估 1-2 天）

#### Step 1: 安装 Shorebird CLI
```bash
# 安装 Shorebird
curl --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/shorebirdtech/install/main/install.sh -sSf | bash

# 登录账号
shorebird login
```

#### Step 2: 初始化项目
```bash
cd frontend
shorebird init
```

#### Step 3: 构建首个发布版本
```bash
# 构建 Release 版本（带热更新能力）
shorebird release android --dart-define=BASE_URL=http://www.olraingin.com:8080

# 生成的 APK 路径：build/app/outputs/bundle/release/app-release.aab
```

#### Step 4: 发布热更新补丁
```bash
# 修改代码后，发布补丁
shorebird patch android

# 用户下次启动时自动下载并应用补丁
```

### 3.3 GoLedger 集成注意事项

1. **首次发布必须走应用商店**  
   Shorebird 只能更新已安装的应用，首个版本必须通过应用商店分发。

2. **不支持的更新类型**
   - ❌ 修改 `AndroidManifest.xml`（如添加权限）
   - ❌ 添加/删除 Flutter 插件依赖
   - ❌ 修改原生 Kotlin/Java 代码
   - ✅ 修改 Dart 代码（UI、业务逻辑）
   - ✅ 修改图片/字体等资源文件

3. **版本管理策略**
   ```
   v1.0.0 (应用商店) → patch 1.0.0+1 (热更新)
                      → patch 1.0.0+2 (热更新)
   v1.1.0 (应用商店) → patch 1.1.0+1 (热更新)
   ```

4. **国内加速方案**（可选）
   - Shorebird 服务器在海外，国内下载慢
   - 可自建 CDN 镜像加速（需额外开发）
   - 或使用阿里云/腾讯云 OSS 做中转

## 七、替代方案补充说明

### 7.1 如果不使用 Shorebird

如果因为某些原因（如预算、合规）无法使用 Shorebird，可考虑：

**方案 A：配置化 UI（轻量级热更新）**
```dart
// 从服务器下载 UI 配置
{
  "home_banner": "新年活动.png",
  "category_icons": {...},
  "theme_color": "#F28C5E"
}

// 根据配置动态渲染
```
- ✅ 成本：零
- ❌ 限制：只能更新配置，无法修改逻辑

**方案 B：延迟使用热更新**
- 先不集成，等应用成熟后再评估
- 初期通过应用商店发版即可

### 7.2 国内替代方案

由于 Shorebird 服务器在海外，如果国内访问确实很慢，可考虑：

1. **自建 Shorebird 镜像服务**（需额外开发）
2. **使用国内类似服务**（目前暂无成熟方案）
3. **接受慢速更新**（非实时更新，用户下次启动时更新）

## 八、FAQ

### Q1: 热更新会影响应用性能吗？
**A**: 不会。Shorebird 在后台下载补丁，下次启动时应用。首次启动可能多 1-2 秒检查更新时间。

### Q2: 用户必须联网才能更新吗？
**A**: 是的。但如果下载失败，应用会继续使用旧版本，不影响正常使用。

### Q3: 可以强制用户更新吗？
**A**: Shorebird 默认是静默更新。如需强制更新，需自行实现版本检查逻辑。

### Q4: 热更新会被应用商店拒绝吗？
**A**: Google Play 允许热更新，但要求：
- 不能修改应用核心功能
- 不能绕过应用商店审核添加新功能
- 建议仅用于 Bug 修复和 UI 调整

### Q5: 如果热更新导致崩溃怎么办？
**A**: Shorebird 支持一键回滚到上一个稳定版本：
```bash
shorebird patch rollback android
```

## 九、总结

### ✅ 强烈推荐 Shorebird 用于 GoLedger

**核心理由**：
1. **零成本**：个人开发者免费额度足够
2. **低风险**：官方背书，技术成熟
3. **高效率**：1-2 天集成，几乎零维护
4. **强需求**：记账应用需要快速修复计算错误等关键 Bug

**实施建议**：
- 先集成 Shorebird，发布支持热更新的版本
- 积累使用经验，观察更新效果
- 如遇国内访问慢，再考虑自建 CDN

**不建议**：
- ❌ 自建热更新系统（投入产出比低）
- ❌ 混合 WebView 方案（体验差）
- ❌ 完全不做热更新（错失快速迭代能力）
